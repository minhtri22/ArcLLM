**Date:** 2026-09-21

**Mode:** specification-only  
**Status:** CANDIDATE — independent QA required before implementation lock.

## 1. Scientific question

Does one fixed **subgroup-32 split-K per-output-row** dataflow materially accelerate ArcLLM's exact batch-1 packed Q4_K decode GEMM shape family versus the frozen generic kernel while preserving the established numerical contract? Only if Q4 passes may the same mechanism be extended to Q6_K.

This is not an end-to-end model experiment and cannot reopen Q3.

## 2. Why this is the one primary mechanism

The frozen decode baseline gives one invocation an entire output row and that invocation serially scans all K. For batch=1 there is no token dimension to amortize as in the prefill tiled kernels.

SA0-CAP proved subgroup size 32, subgroup arithmetic, subgroup-size-control and full-subgroup support on the exact Arc 140V. The candidate therefore changes only work partitioning:

```text
baseline:
1 invocation → 1 output row → scan all K

SA1:
1 subgroup (32 lanes) → 1 output row
each lane → K-strided packed dequant + FP32 partial dot
subgroup reduction → one row result
lane 0 → store
```

One workgroup is frozen at 128 invocations = four 32-lane subgroups = four output rows.

No fusion, pre-dequantization, matrix staging, cooperative matrix, local-size search or subgroup-size search belongs to SA1.

## 5. Capability route disposition

### Selected

- required subgroup size: 32;
- full subgroups required;
- subgroup arithmetic reduction;
- local size: 128×1×1;
- four subgroups/workgroup;
- one subgroup/output row;
- direct packed Q4_K/Q6_K bytes;
- FP32 partial accumulation.

### Explicitly deferred

`VK_KHR_cooperative_matrix` is available on the device but **not used in SA1**. Q4_K/Q6_K require packed metadata/dequantization; converting them to matrix-friendly INT8/FP16 operands would introduce a second staging mechanism and destroy single-mechanism attribution.

Subgroup 16 and all workgroup/tile variants are also forbidden.

## 6. Deterministic component fixtures

No model is loaded.

Each cell has four deterministic packed fixture banks generated by exact SplitMix64 seeds:

```text
0x5341315046495831
0x5341315046495832
0x5341315046495833
0x5341315046495834
```

Timing rotates bank `pair_index mod 4`; baseline and candidate use the same bank within a pair. This prevents a single permanently hot weight buffer from defining the study while preserving matched A/B data.

Maximum per-cell process allocation is 256 MiB. No pre-dequant buffer or global scratch is allowed.

## 7. Correctness contract

Before any performance adjudication:

- baseline vs CPU reference: PASS;
- candidate vs CPU reference: PASS;
- candidate vs baseline: PASS;
- every output finite;
- max_abs <= **0.02**;
- RMSE <= **0.005**.

These are the established P7 packed-kernel tolerances. Changing accumulation order is allowed; changing quantization semantics is not.

Correctness is checked on fixture banks 0 and 3 for every measured shape.

## 8. Timing protocol

Exact target remains Core Ultra 7 258V / Arc 140V / driver 32.0.101.8860 / Balanced / AC online.

Primary metric is Vulkan GPU timestamp duration around one dispatch. SA0 established 64 timestamp-valid bits and 52.0833321 ns timestamp period.

Two separate processes are mandatory:

```text
A: cells forward
B: cells reverse
```

Per cell/process:

- 10 warmups per arm;
- 30 measured A/B pairs;
- pair parity alternates baseline→candidate and candidate→baseline;
- process B starts with reverse parity;
- no sample deletion/outlier deletion;
- process pooling forbidden.

Pipeline creation and host submit/fence time are excluded from the primary metric. CPU wall time is descriptive only.

## 9. Frozen performance gate

For each process separately:

```text
cell speedup = median baseline GPU ns / median candidate GPU ns
```

### Q4 primary stage

Across the five Q4 cells:

- geometric mean speedup >= **1.50×** in process A;
- geometric mean speedup >= **1.50×** in process B;
- every individual Q4 cell >= **1.10×** in both A and B.

Q4 must pass before Q6 implementation is allowed.

### Q6 extension

Across the two Q6 cells:

- geometric mean speedup >= **1.50×** independently in A and B;
- every Q6 cell >= **1.10×** independently in A and B.

The 1.50× gate deliberately requires a successor-architecture effect larger than the historical 1.10× P7 tuning gate. It is frozen before candidate data.

## 10. Resource budget

Candidate is fixed to:

- 128 invocations/workgroup;
- subgroup size 32;
- four output rows/workgroup;
- **0 bytes explicit shared memory**;
- **0 bytes extra global scratch**;
- same W/X/B/Y binding semantics;
- no pre-dequant pass;
- no copy/staging pass;
- no per-lane arrays;
- <=16 explicit live scalar values/lane by source review.

Physical register count is not a portable Vulkan-core observable. If compiler/driver statistics expose it, it is recorded descriptively and cannot become a post-hoc gate.
